# 羊毛福利专区 · 投稿与审核指南

面向两类人：**投稿者**（怎么提交）和**审核者**（怎么判、怎么上线）。

---

## 一、投稿者：三步提交

1. 打开仓库 → `Issues` → `New issue` → 选 **「羊毛投稿」**
2. 按表单填。带 `*` 的必填，**「你是怎么核实的」一定要写实**
3. 提交，等审核结果（在本 Issue 里回复，不另行通知）

### 投稿被退回的常见原因

| 原因 | 说明 |
|---|---|
| 没写核实来源 | 「我是听说的」「网上看到的」一律不收 |
| 链接指向首页 | 要能直接到领取页，不然用户找不到 |
| 额度写得太虚 | 「很多」「超值」「大额」—— 写具体数字 |
| 跟工具库重复 | 只描述工具多好用的，那是工具库的内容，不是羊毛 |
| 站点已收录 | 先搜一下专区里有没有，重复投稿会被合并 |

### 什么样的羊毛值得投

- ✅ 明确的免费额度、免费时长、免费次数
- ✅ 学生 / 教育 / 开源 / 新用户优惠
- ✅ 有具体门槛说明（哪怕门槛高，写清楚也有价值）
- ❌ 「限时打折」「首月一折」这类短期营销
- ❌ 需要邀请多少人才能拿的裂变活动

## 二、审核者：五步上线

### 1. 验真（最重要）

按投稿者写的核实路径**自己再走一遍**。打不开、页面改了、额度对不上 → 直接在 Issue 里说明并关闭。

每个人都会写错，尤其是额度数字。**不要相信投稿，只相信你亲眼看到的。**

### 2. 判断价值

- 这条能让多少人受益？（越普惠权重越高）
- 门槛是不是高到没意义？（需绑卡 + 需外网 + 限时 = 基本没人用）
- 跟已有条目是不是重复？

### 3. 转成数据

在 `data/wool.ts` 的 `WOOL` 数组里加一条：

```ts
{
  id: "英文短横线唯一标识",
  toolId: "data/tools.ts 里的 id，站点未收录则不填",
  name: "工具名",
  quota: "白嫖额度",
  gate: "零门槛",            // 零门槛 | 需学生 | 需绑卡 | 需外网
  validity: "长期",          // 长期 | 限时 | 已失效
  deadline: "2026-12-31",   // 限时/已失效才填
  how: "一句话领取方式",
  trap: "坑点提示",           // 选填
  href: "https://领取链接",
  weight: 70,               // 越大越靠前
  checkedAt: "2026-09-06",  // 你实际核实这天的日期
}
```

**`checkedAt` 填你审核当天的日期，不要照抄投稿者的。**

### 4. 定权重 `weight`

| 档位 | 适用 |
|---|---|
| 100 | 零门槛 + 长期 + 额度实在 |
| 70-90 | 零门槛但额度一般，或需简单验证 |
| 40-60 | 需学生 / 教育认证 |
| 20-30 | 需绑卡、需外网、限时 |
| 0-10 | 快要过期，或门槛很高 |

### 5. 回复并关闭

在 Issue 里回复结果（已上线 / 不通过 + 原因），打上 `已上线` 或 `已拒绝` 标签后关闭。

**投稿者付出了劳动，哪怕不通过也要给个说法。**

---

## 三、日常维护

### 失效条目不要删

额度失效后，把 `validity` 改成 `"已失效"` 并补上 `deadline`。

置灰保留的理由：让人知道「这个没了，别白跑」。删掉的话，用户会以为自己记错了，还会再来找一遍。

### 定期复查

建议每月扫一遍 `data/wool.ts`，重点看：

- `validity: "限时"` 且 `deadline` 已过期的
- `checkedAt` 超过 90 天的长期条目

---

## 四、标签约定

在仓库 `Issues → Labels` 里建这几个标签：

| 标签 | 颜色 | 用途 |
|---|---|---|
| `羊毛投稿` | 紫 #5b4be6 | 新投稿（表单自动打） |
| `已上线` | 绿 | 审核通过并合入 |
| `已拒绝` | 灰 | 未通过，原因写在评论里 |
| `待复核` | 黄 | 信息存疑，等站长二次确认 |

> ⚠️ `羊毛投稿` 这个标签**必须提前建好**，不然 Issue 表单提交会失败。
